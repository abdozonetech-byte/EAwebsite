The practical prompt engineering guide

A practical way to ask, refine, compare and verify. No promise of infallible answers or universal model rankings.

01 / Method

What is prompt engineering?

It is the design of instructions and context for a reviewable task. A prompt cannot guarantee truth or quality: it helps organise the work, expose assumptions and make limitations easier to inspect.

02 / Method

Why context matters

Describe the audience, objective, resources and constraints. Provide only necessary, authorised information. Missing information should lead to a focused question or an explicit assumption, not an invented fact.

03 / Method

Define a clear task

Ask for a concrete action and deliverable. “Prepare three neutral interview questions” is more reviewable than “help with my business.” Separate the need, proposed solution and non-goals.

Try a related prompt ↗
04 / Method

Choose an output format

Specify sections, a table or JSON when it helps the reader. Structure makes review easier but does not establish accuracy. For code and data, include expected checks and explain which tests still need execution.

05 / Method

Use editable variables

Square brackets mark values to replace. Names may contain spaces, such as [TARGET AUDIENCE]. Empty fields remain visible. Customisation never changes the original prompt, and sensitive information should not be entered.

06 / Method

Refine without losing constraints

Compare the response with your criteria, identify a specific error and request a bounded correction. Preserve useful constraints and change one dimension at a time. Keep versions when you need to explain a decision.

07 / Method

Avoid common mistakes

Do not ask for invented numbers to complete a report. Do not mistake an example for evidence or polished wording for a verified source. Never paste private data into an unapproved tool.

08 / Method

Evaluate the response

Check task fit, facts, sources, assumptions, safety and feasibility. Use relevant tests for code and inspect cited passages for research. A model’s self-assessment is not independent proof.

09 / Method

Choose tools by task

General assistants can help structure and draft. Coding agents need repositories, tools and permissions; media tools need the requested format capabilities. GPT, Claude and Gemini capabilities depend on the product and configuration. Library labels are capability suggestions, not model-test results or a universal ranking.

10 / Method

Verify independently when needed

Check current, specialised, consequential and quantitative claims against suitable sources. Preserve uncertainty when evidence is missing or conflicting. Obtain approval for external actions and distinguish drafting, authorisation and execution.
